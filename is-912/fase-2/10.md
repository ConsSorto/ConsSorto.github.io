# ⚛️ Clase 10: Desarrollo Frontend Moderno, Virtual DOM y Arquitectura de Proyecto

## 📖 Teoría: Anatomía del Navegador y el Motor de React

En arquitecturas API-First, el servidor (.NET) entrega datos (JSON), y el navegador asume la renderización. Para entender por qué la industria estandarizó React para esta tarea, debemos analizar el problema de rendimiento de los navegadores clásicos.

### 1. El Problema del DOM Real (Document Object Model)
El DOM es la representación en forma de árbol que el navegador construye a partir del HTML. Cada vez que cambiamos un dato mediante JavaScript tradicional (ej. jQuery), el navegador debe recalcular posiciones, colores y repintar la pantalla (procesos llamados Reflow y Repaint). Modificar el DOM directamente es una operación computacionalmente costosa y lenta.

### 2. La Solución: El Virtual DOM y el Proceso de Reconciliación
React intercepta este problema creando un Virtual DOM: una copia exacta, pero ligera y en memoria RAM (sin renderizado gráfico).
Cuando los datos cambian, React actualiza su Virtual DOM. Luego, ejecuta un algoritmo llamado Diffing (comparación) para detectar exactamente qué nodos cambiaron respecto a la versión anterior. Finalmente, aplica una "actualización en lote" (Batch Update) al DOM Real, modificando únicamente lo estrictamente necesario.

## 💻 Desarrollo Práctico: Inicialización y Análisis Estructural
Vamos a crear el proyecto Frontend que vivirá dentro de nuestro Monorepo, utilizando Vite (el estándar de compilación ágil moderno que reemplaza a Webpack, ofreciendo recarga en milisegundos).

### 1. Scaffolding del Proyecto
En la terminal, desde la raíz del monorepo (fuera de la carpeta backend), ejecutamos:

```bash
# Crea la estructura base de React con Vite
npm create vite@latest frontend -- --template react

# Instalamos las librerías declaradas en el manifiesto
cd frontend
npm install
```

### 2. Análisis Forense de la Estructura (El esqueleto del sistema)
Abre la nueva carpeta frontend en tu IDE. Como analistas de sistemas, no escribimos código sin entender dónde lo estamos poniendo. Esta es la radiografía del proyecto:

* **📁 node_modules/**: Es el motor pesado. Aquí residen físicamente todas las librerías y dependencias de nuestro proyecto (incluyendo React y Vite). Importante: Esta carpeta jamás se sube a Git.
* **📁 public/**: Contiene activos estáticos (imágenes, favicons) que el compilador de Vite ignora. Se copian tal cual al servidor de producción.
* **📁 src/ (Source)**: El corazón de la aplicación. Aquí vivirá todo nuestro código.
* **📄 main.jsx**: El Punto de Entrada (Entry Point). Es el archivo principal que arranca la aplicación. Aquí React toma el componente raíz y lo "inyecta" en el HTML.
* **📄 App.jsx**: El Componente Raíz. Es el contenedor maestro. Todas las vistas, rutas y componentes de nuestro sistema nacerán como hijos de este archivo.
* **📄 index.css / App.css**: Hojas de estilo globales y específicas del componente raíz.
* **📄 index.html**: El lienzo en blanco. A diferencia de PHP, aquí no hay código dinámico. Solo contiene una etiqueta crítica: `<div id="root"></div>`. React utilizará este div vacío para renderizar toda la interfaz gráficamente.
* **📄 package.json**: El Manifiesto del proyecto. Actúa como el `.csproj` de .NET. Define el nombre del proyecto, los scripts de arranque (ej. `npm run dev`) y el listado estricto de dependencias y sus versiones.
* **📄 vite.config.js**: El archivo de configuración del compilador. Aquí podemos ajustar puertos del servidor local o configurar proxies para eludir problemas de red temporales.

### 3. Levantando el Entorno de Desarrollo
Ejecutamos el servidor local de Vite:

```bash
npm run dev
```

Al navegar a `http://localhost:5173`, veremos nuestra aplicación corriendo.
